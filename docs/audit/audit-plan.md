# 产品审查方案（真实用户 + 作业合规）

> 状态：方案。检查项是待执行的判据，不是结论。疑似问题见文末，须由阶段 2–3 证伪或证实。
> 日期：2026-10-11。锚点：`checkpoint-pre-audit`。

## A. 审查维度

| 维度 | 审什么 |
|---|---|
| D1 作业红线合规 | 程序是否会**给出结论**？是否有任何路径替用户产出判断？ |
| D2 教材 10 步对齐 | 每步的输入区是否**真的对应**教材那一步？缺什么？多余的什么？ |
| D3 首次使用可理解性 | 一个没读过说明书的人，能否知道下一步该做什么？ |
| D4 课堂演示可行性 | 前 5 步能否在 **7–8 分钟内**走完？交互步数是多少？ |
| D5 功能有效性 | 证据关联 / 修订对比 / 形式校验 / 导出，**实际有没有产生有用的效果**？ |
| D6 数据安全与健壮 | 保存、刷新、导入失败、`localStorage` 不可用时是否安全降级？ |
| D7 视觉与投影可读性 | 字号、对比度、密度，在 1024×768 与 1280×720 下是否可读？ |
| D8 交付一致性 | 导出素材能否直接支撑报告模板？离线单文件是否仍成立？ |

增补：D9 并发与回归 — 修复不得删既有能力、不得把自测打进 `dist/index.html`。

## B. 检查项

自动化等级：**A** 可完全自动化；**B** 脚本产证据、需人判断；**C** 只能人工。

### D1 作业红线合规

| ID | 检查项 | 判定标准（可证伪） | 证据形式 | 等级 |

| D1-2 | 结论类字段写入路径 | 除用户输入、用户确认的导入、用户点的快照恢复外，不存在把句子写入回答/结论字段的代码路径 | 调用点清单 | B |
| D1-3 | 第 8 步无参考观点 | 第 8 步 DOM 与数据中 `referenceLevel3 === null`，且无「参考观点」可点入口 | DOM + `CASE_DATA.steps[7]` | A |

## C. 无法自动化、需 PI 人工确认

1. **D1-1 语境**：命中「结论 / 答案 / 建议」时，是否在教学语境里越界（例如「我的判断」vs「程序给出的结论」）。
2. **D2-13 / D8-3**：导出素材与 `Template_3.tex` 的差距，是否足以支撑 1.2 报告，还是必须手抄重组。
3. **D3-4**：不看说明书的组员，10 秒内能否说出当前步要做什么。
4. **D4 时长**：前 5 步真实讲述（含口播案例）能否落在 7–8 分钟，脚本只能给交互次数。
5. **D7-4**：1024×768 投影后排可读性（对比度、密度、装饰是否抢注意力）。
6. **引导例句**：`guidance.js` 里的「提问示意」会不会被听众当成参考答案。
7. **三个反思问题**：属于报告，不在程序内；需确认 1.2 材料是否另备，程序不代写。
8. **演示彩排**：谁点鼠标、哪一屏停住讲架构（2–3 分钟）——产品无法自证。

## D. 疑似问题（待证伪，不是结论）

| 假设 | 计划用什么推翻或坐实 |
|---|---|
| 首屏不知道从哪开始 | D3-1 首屏 DOM：是否有唯一主按钮与步骤说明 |
| 10 步内容雷同 | D2-1 逐步控件类型是否不同 |
| 输入区缺少引导与示例 | D3-2 提示面板默认是否 hidden |
| 证据关联入口隐蔽、关联后无效果 | D5-1 关联后面板上是否出现理由 |
| 修订对比只有统计行 | D5-3 `.revision-diff-list` 是否有条目 |
| 形式校验太弱或太烦 | D5-4 提醒是否在折叠面板里、是否阻断 |
| 演示模式不存在或不完整 | D4-2 检索「课堂展示」入口；`presentation` 是否曾被赋值为非 null |
| 字体小、投影看不清 | D7-2 实测 px |
