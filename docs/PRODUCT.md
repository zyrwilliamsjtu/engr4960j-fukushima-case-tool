# 产品功能草案 v0.1 — 福岛案例分析引导工具

> 用途：与组员同步意见用。建议直接存为 `docs/PRODUCT.md`，评审后把结论回填到 `docs/CONTRACT.md`。
> 标注说明：⚠️ = 需组员确认；✅ = 已定，不用再议。

---

## 一、产品定位

**一句话**：一个离线单文件网页，带用户按教材 10 步分析法，一步步完成福岛第一核电站事故的案例分析。

**它是什么** ✅
- 引导式**工具**，不是自动分析器。
- 用户填答案，程序负责：给背景 → 抛引导问题 → 检查格式 → 提醒遗漏 → 回显 → 导出素材。

**它不是什么** ✅（这几条是红线，遇到分歧以此为准）
- ❌ 不接任何 API、不联网、不需要服务器。
- ❌ 不生成结论、不生成报告正文。
- ❌ 不覆盖多个案例，只做福岛。
- ❌ 没有账号系统、没有数据库、没有多人协作。

**为什么这么做**（给组员的背景）
- 交付方式是**一封邮件里的单个 HTML**，名字固定 `Group #… 4960`，TA 在教室电脑双击打开。后端没地方放。
- 运行时零网络 ⇒ 结果确定、可排练、可复现、演示不会崩。
- AI 的使用挪到**开发阶段**（查资料、草拟引导问题），对话截图正好作为 1.2 要交的 vibe-coding 证据。

---

## 二、三条设计铁律 ✅

1. **人先写，程序后开口。** 用户没提交自己的答案前，"参考视角"按钮灰着。
2. **只有引导，没有判决。** 程序输出永远是问题、检查、提醒，不出现"正确答案是…"。
3. **结论槽位只能人填。** 第 8 步的结论框默认空白，代码层面禁止任何自动写入。

## 四、10 步功能规格

### 共同套路（每步一致）
背景说明 → 引导问题 → 输入区 → 校验 → 参考视角（门控）→ 下一步。

### 逐步骤

| 步 | 名称 | 输入区形态 | 校验规则（不通过不给过） | 参考内容 |
|---|---|---|---|---|
| 1 | 识别伦理问题 | 条目列表，每条含"问题"+"涉及主体（选填）" | 至少 5 条；每条须为**问句**（含"是否/应该/该不该"或问号），否则标黄 | 福岛事实时间线（只读） |
| 2 | 聚焦 | 从第 1 步的列表里**勾选 2 条**+理由文本框 | 恰好选 2 条；理由非空；可"重写以涵盖子问题" | 教材对"完整性优于广度"的说明 |
| 3 | 相关事实 | **三个分类格子**：材料 / 个人 / 组织；外加"缺失事实"栏 | 每类 ≥2 条；缺失事实 ≥2 条 | 已收录事实库（只读、**不可一键复制**） |
| 4 | 合理假设 | 每条假设 = 假设内容 + **依据字段** | 每条依据非空，否则整条标黄；≥2 条 | 教材对"假设不能开放式"的说明 |
| 5 | 定义澄清 | 从高亮词中选"价值含义词"→ 每条填两栏：①别人可能怎么理解 ②我打算怎么用 | 至少澄清 2 个词，两栏都非空 | 已标注的候选词（如"责任""安全""合规"） |
| 6 | 伦理分析 | ①原则卡片多选 ②**拖拽排序器**（处理冲突）③排序理由 ④"是否有原则不足" | 选 ≥3 条原则；有冲突时必须排序并写理由 | 原则清单（来自教材附录 I，10–15 条） |
| 7 | 过程回顾 | **自动回显第 1–6 步全部答案**，每条一个"需修订 / 无需修订"开关 | 全部条目走完；勾"需修订"的可点击跳回 | 偏见自查清单（勾选式） |
| 8 | 得出结论 | 回显第 2 步选定的问题 → 结论框 + 理由框（纯文本） | 两者都非空；**程序不提供任何措辞建议** | 无（此步禁用参考视角） |
| 9 | 实践约束 | 预设"缓解/豁免条件"清单勾选 + 说明 | 勾选 ≥1 条并说明，或明确勾"无" | 教材对 excusing/mitigating conditions 的定义 |
| 10 | 避免问题 | 条目列表 | **至少 3 条** | 无 |

**第 7 步的"自动回显"是关键功能**——它让"迭代"这件事变成用户能看见的动作，正好呼应教材强调的"案例分析是迭代过程"。

## 六、数据契约 v1 ⚠️ 重点确认

### 静态数据（你维护，`src/data/fukushima.js`，挂全局变量）

```js
window.CASE_DATA = {
  meta: { id: "fukushima", title: "福岛第一核电站事故", dataVersion: "1.0" },
  timeline: [ { date, event, sourceId } ],
  sources: [ { id, title, publisher, year, url } ],
  facts: {
    material:     [ { id, text, sourceId } ],
    individual:   [ { id, text, sourceId } ],
    organization: [ { id, text, sourceId } ]
  },
  valueWords: [ { word, whyVague } ],          // 第 5 步候选词
  principles: [ { id, name, desc, sourceId } ],// 第 6 步卡片
  constraints: [ { id, label, desc } ],        // 第 9 步清单
  biasChecks: [ { id, label } ],               // 第 7 步自查
  steps: [ /* 10 条，结构见下 */ ]
};
```

**单步结构**

```js
{
  id: 1,
  key: "identify",
  name: "识别伦理问题",
  presentInClass: true,        // 前 5 步为 true
  intro: "背景说明文本…",
  prompts: ["引导问题1", "引导问题2"],
  fields: [
    { key: "issues", type: "list", label: "伦理问题",
      min: 5, itemSchema: ["text:question", "actor:optional"], hint: "…" }
  ],
  checks: ["minItems:5", "mustBeQuestion"],
  reference: { type: "timeline" }   // 或 facts / text / null
}
```

**可用字段类型**（组员按这个写渲染组件即可）：
`text` · `textarea` · `list`（带 min/max 的条目列表） · `question`（问句校验） · `bucketedFacts`（三分类格子） · `assumption`（内容+依据绑定） · `clarify`（双栏：他人理解/我的用法） · `multiSelect` · `rankList`（拖拽排序） · `checkList` · `review`（只读回显+开关）

### 用户状态（运行时，localStorage）

```js
{
  stateVersion: "1.0",
  caseId: "fukushima",
  currentStep: 3,
  startedAt, updatedAt,
  steps: {
    1: { completed: true,  fields: { issues: [...] }, revisedAt },
    2: { completed: false, fields: { chosen: ["1a","1c"], reason: "" } }
  }
}
```

⚠️ **契约冻结规则**：这份字段一旦组员开始动手，任何改动必须**先升 `dataVersion`/`stateVersion` 并群里通知**，否则界面静默崩，排查很费时间。

## 七、技术约束（硬性，必须全员遵守）✅

| 约束 | 原因 |
|---|---|
| 原生 JS，不用 React/Vue | 单文件、无构建依赖 |
| 不用 CDN、不引外部 CSS/JS | 教室电脑可能无网，且要能双击打开 |
| 不用 ES Module（`import`/`export`） | `file://` 下会被 CORS 拦 |
| 不用 `fetch()` 读本地 JSON | 同上，会失败 |
| 所有数据写成 `.js` 挂全局变量 | 唯一可行的离线加载方式 |
| 最终由 `tools/build.py` 内联为单个 `dist/index.html` | 交付形态 |
